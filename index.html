Waiter is not current.

Step 1 of 4 · Waiting

Task B is queued for the proxy lock. Its pi_blocked_on field points to that lock.

Buggy path

Cleanup operates on Task A (`current`) instead of Task B (`waiter->task`). The wrong task's lock and priority state are used; Task B can retain a stale blocked-on pointer.

Fixed path

Cleanup consistently targets Task B, including its PI lock, blocked-on state, and priority-chain adjustment. The waiter is removed from the correct state.

The issue is in the Linux kernel's real-time mutex code, not in an Android application API. Android devices may use Linux kernels, but exposure depends on the device's kernel and vendor fixes. NVD record
